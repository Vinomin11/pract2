# dependency-graph

Инструмент визуализации графа зависимостей пакетов Cargo (Rust).
Учебный проект по дисциплине «Конфигурационное управление», вариант 17.

Готовые менеджеры пакетов и сторонние библиотеки для получения
зависимостей не используются: только стандартная библиотека Python.

## 1. Общее описание

Приложение запускается из командной строки. Все настройки задаются
опциями командной строки. На текущем этапе (этап 2) приложение
получает и выводит **прямые зависимости** заданного пакета Cargo.

Данные берутся из индекса реестра Cargo (по умолчанию
`https://index.crates.io`). Это обычные текстовые файлы по HTTP,
менеджер пакетов (`cargo`) не используется. Для каждого пакета в индексе
есть файл, где одна строка JSON описывает одну версию пакета, в том числе
список её зависимостей. Приложение берёт последнюю версию, которая не
отозвана (`yanked`).

Требуется Python 3.8 или новее. Устанавливать ничего не нужно.

## 2. Описание функций и настроек

### Настройки (опции командной строки)

| Опция | Описание |
|-------|----------|
| `--package`, `-p` | Имя анализируемого пакета |
| `--repo`, `-r` | URL репозитория (режим `remote`) или путь к файлу тестового репозитория (режим `test`) |
| `--mode`, `-m` | Режим работы: `remote` (по умолчанию) или `test` |

Правила проверки:

* имя пакета в режиме `remote`: буквы, цифры, `-` и `_`, первой должна
  быть буква;
* имя пакета в режиме `test`: одна большая латинская буква;
* в режиме `remote` репозиторий должен быть URL с `http://` или
  `https://`;
* в режиме `test` репозиторий должен быть существующим файлом.

При ошибке выводится сообщение в stderr, код завершения 2.

Какие зависимости считаются прямыми: только обычные (`normal`) и не
помеченные `optional`. Зависимости для тестов (`dev`), для сборки
(`build`) и необязательные пропускаются.

Режим `test` пока не реализован (появится на этапе 3).

### Модули

| Файл | Назначение |
|------|------------|
| `src/main.py` | Точка входа, вывод зависимостей |
| `src/config.py` | Разбор и проверка параметров командной строки |
| `src/cargo_index.py` | Получение зависимостей из индекса реестра |
| `src/errors.py` | Исключения приложения |

Функции `src/cargo_index.py`:

* `index_path(name)` — путь файла пакета в индексе
  (`serde` -> `se/rd/serde`);
* `fetch_text(url)` — скачать текст по URL, ошибки превращаются
  в `RepositoryError`;
* `parse_versions(text)` — разобрать файл индекса в список версий;
* `pick_latest(versions)` — выбрать последнюю неотозванную версию;
* `direct_dependencies(version)` — имена прямых зависимостей версии;
* `fetch_dependencies(package, repo_url)` — всё вместе.

## 3. Сборка и тесты

Сборка не требуется. Запуск тестов (из корня репозитория):

```
python -m unittest discover -s tests -t .
```

## 4. Примеры использования

Запуск (Linux/macOS: `./run.sh`, Windows: `run.bat`):

```
$ ./run.sh -p serde -r https://index.crates.io
Прямые зависимости пакета serde:
  serde_core
```

Список зависимостей зависит от текущей версии пакета в реестре, поэтому
у вас результат может отличаться.

Примеры обработки ошибок:

```
$ ./run.sh -p nosuchcrate123 -r https://index.crates.io
Ошибка: пакет не найден: https://index.crates.io/no/su/nosuchcrate123

$ ./run.sh -p serde -r http://localhost:1
Ошибка: не удалось загрузить http://localhost:1/se/rd/serde: ...

$ ./run.sh -p serde
Ошибка: не задан репозиторий (--repo)

$ ./run.sh -p serde -r ftp://x
Ошибка: некорректный URL 'ftp://x': ожидается http:// или https://

$ ./run.sh -p A -r README.md -m test
Ошибка: режим test будет доступен на этапе 3
```
