# dependency-graph

Инструмент визуализации графа зависимостей пакетов Cargo (Rust).
Учебный проект по дисциплине «Конфигурационное управление», вариант 17.

Готовые менеджеры пакетов и сторонние библиотеки для получения
зависимостей не используются: только стандартная библиотека Python.

## 1. Общее описание

Приложение запускается из командной строки. Все настройки задаются
опциями командной строки. На текущем этапе (этап 4) приложение строит
**граф зависимостей** заданного пакета с учётом транзитивности и выводит
его, сообщает о циклических зависимостях, а также умеет выводить
**обратные зависимости** пакета (кто от него зависит).

Граф строится обходом в ширину (BFS) без рекурсии: очередь пакетов
и множество уже встреченных пакетов. Каждый пакет обрабатывается один
раз, поэтому циклические зависимости не приводят к зацикливанию.

Два режима работы:

* `remote` — зависимости берутся из индекса реестра Cargo
  (по умолчанию `https://index.crates.io`). Это текстовые файлы по HTTP,
  менеджер пакетов (`cargo`) не используется. Для каждого пакета в индексе
  есть файл, где одна строка JSON описывает одну версию пакета. Берётся
  последняя версия, которая не отозвана (`yanked`).
* `test` — граф читается из текстового файла (тестовый репозиторий),
  пакеты называются большими латинскими буквами.

Требуется Python 3.8 или новее. Устанавливать ничего не нужно.

## 2. Описание функций и настроек

### Настройки (опции командной строки)

| Опция | Описание |
|-------|----------|
| `--package`, `-p` | Имя анализируемого пакета |
| `--repo`, `-r` | URL репозитория (режим `remote`) или путь к файлу тестового репозитория (режим `test`) |
| `--mode`, `-m` | Режим работы: `remote` (по умолчанию) или `test` |
| `--reverse` | Вывести обратные зависимости пакета вместо графа. Только в режиме `test` |

Правила проверки:

* имя пакета в режиме `remote`: буквы, цифры, `-` и `_`, первой должна
  быть буква;
* имя пакета в режиме `test`: одна большая латинская буква;
* в режиме `remote` репозиторий должен быть URL с `http://` или
  `https://`;
* в режиме `test` репозиторий должен быть существующим файлом;
* `--reverse` допустима только в режиме `test`: в реестре нет списка
  всех пакетов, поэтому узнать, кто зависит от пакета, можно только
  по полностью известному тестовому репозиторию.

Обратные зависимости ищутся тем же алгоритмом BFS, но по перевёрнутому
графу всего файла (учитываются и пакеты, не достижимые из заданного).
В список входят и прямые, и транзитивные потребители. Сам пакет попадает
в список только если он зависит от себя (участвует в цикле).

При ошибке выводится сообщение в stderr, код завершения 2.

Какие зависимости считаются прямыми: только обычные (`normal`) и не
помеченные `optional`. Зависимости для тестов (`dev`), для сборки
(`build`) и необязательные пропускаются.

### Формат файла тестового репозитория

Одна строка на пакет: имя, двоеточие, зависимости через пробел.
Пустые строки и строки, начинающиеся с `#`, игнорируются.
Пакет без зависимостей записывается как `D:`. Пакет, который только
упомянут как зависимость, считается пакетом без зависимостей.

```
# A зависит от B и C
A: B C
B: D
C: D
D:
```

Готовые примеры лежат в папке `examples/`: `simple.txt` (ромб),
`cycle.txt` (цикл), `big.txt` (несколько циклов и самозависимость).

### Модули

| Файл | Назначение |
|------|------------|
| `src/main.py` | Точка входа, выбор источника данных, вывод графа |
| `src/config.py` | Разбор и проверка параметров командной строки |
| `src/cargo_index.py` | Получение зависимостей из индекса реестра |
| `src/graph_file.py` | Чтение файла тестового репозитория |
| `src/graph.py` | Построение графа (BFS) и поиск циклов |
| `src/errors.py` | Исключения приложения |

Функции `src/cargo_index.py`:

* `index_path(name)` — путь файла пакета в индексе
  (`serde` -> `se/rd/serde`);
* `fetch_text(url)` — скачать текст по URL, ошибки превращаются
  в `RepositoryError`;
* `parse_versions(text)` — разобрать файл индекса в список версий;
* `pick_latest(versions)` — выбрать последнюю неотозванную версию;
* `direct_dependencies(version)` — имена прямых зависимостей версии;
* `fetch_dependencies(package, repo_url)` — всё вместе.

Функции `src/graph_file.py`:

* `parse_line(line, number)` — разобрать строку `A: B C`;
* `load_graph_file(path)` — загрузить весь файл в словарь
  `{пакет: [зависимости]}`.

Функции `src/graph.py`:

* `build_graph(start, get_dependencies)` — BFS без рекурсии, возвращает
  словарь `{пакет: [зависимости]}` в порядке обхода. Источник данных
  передаётся функцией, поэтому один и тот же алгоритм работает и с реестром,
  и с тестовым файлом;
* `lookup_in(graph)` — функция зависимостей по готовому графу;
* `find_cycle_nodes(graph)` — пакеты, входящие в циклы;
* `reverse_graph(graph)` — перевернуть все рёбра графа;
* `reverse_dependencies(graph, package)` — пакеты, которые зависят
  от `package` (BFS по перевёрнутому графу).

## 3. Сборка и тесты

Сборка не требуется. Запуск тестов (из корня репозитория):

```
python -m unittest discover -s tests -t .
```

## 4. Примеры использования

Запуск (Linux/macOS: `./run.sh`, Windows: `run.bat`).

Реальный реестр:

```
$ ./run.sh -p serde -r https://index.crates.io
```

Тестовый репозиторий без циклов (`examples/simple.txt`):

```
$ ./run.sh -p A -r examples/simple.txt -m test
Граф зависимостей пакета A:
  A -> B, C
  B -> D
  C -> D
  D -> (нет)
Циклических зависимостей нет
```

Тестовый репозиторий с циклом (`examples/cycle.txt`):

```
$ ./run.sh -p A -r examples/cycle.txt -m test
Граф зависимостей пакета A:
  A -> B
  B -> C
  C -> A, D
  D -> (нет)
Циклические зависимости: A, B, C
```

Другой стартовый пакет: пакет E в `cycle.txt` зависит от A, поэтому
в его граф попадает весь цикл. Пакет X в `big.txt` зависит от A:

```
$ ./run.sh -p X -r examples/big.txt -m test
Граф зависимостей пакета X:
  X -> A
  A -> B, C
  B -> D, E
  C -> E, F
  D -> G
  E -> G, B
  F -> F, H
  G -> (нет)
  H -> G
Циклические зависимости: B, E, F
```

Здесь есть цикл B -> E -> B и самозависимость F -> F.

Обратные зависимости (`--reverse`), ромб `examples/simple.txt`:

```
$ ./run.sh -p D -r examples/simple.txt -m test --reverse
Обратные зависимости пакета D (кто от него зависит):
  B
  C
  A

$ ./run.sh -p A -r examples/simple.txt -m test --reverse
Обратные зависимости пакета A (кто от него зависит):
  (нет)
```

Файл с несколькими циклами и пакетом X, который не виден из A
(`examples/big.txt`):

```
$ ./run.sh -p G -r examples/big.txt -m test --reverse
Обратные зависимости пакета G (кто от него зависит):
  D
  E
  H
  B
  C
  F
  A
  X
```

Пакет в цикле зависит сам от себя (`examples/cycle.txt`):

```
$ ./run.sh -p A -r examples/cycle.txt -m test --reverse
Обратные зависимости пакета A (кто от него зависит):
  C
  E
  B
  A
```

Ошибки:

```
$ ./run.sh -p serde -r https://index.crates.io --reverse
Ошибка: опция --reverse работает только в режиме test

$ ./run.sh -p Z -r examples/simple.txt -m test
Ошибка: пакет Z не описан в файле examples/simple.txt

$ ./run.sh -p A -r bad.txt -m test
Ошибка: строка 1: ожидается формат 'A: B C'

$ ./run.sh -p serde -r ftp://x
Ошибка: некорректный URL 'ftp://x': ожидается http:// или https://
```
